# 几猫国产3A大作 — 局域网联机对战版设计

日期：2026-11-11 ｜ 状态：已获用户批准

## 目标

单机版 HTML FPS 改造成局域网 1v1 联机：玩家输入服务器地址进入，双方可互相攻击，同时保留原有 PvE 任务与 AI 敌人。

## 已确认的玩法决策

- **模式 C：混战** — 双方玩家 + AI 敌人同时在场。
- **任务保留** — 切三处中继→撤离照常；击杀数单独计分；谁先到达撤离点即任务结束（双方同队，均判任务完成）。
- **死亡 5 秒重生** — 任务进度（已切断中继）保留，不走单机的"任务失败重开"流程。

## 架构

### 服务器 `server.py`（Python 3 标准库，零依赖，单文件）

- 同一端口提供：
  - HTTP：`/` 返回游戏 HTML（`http://主机IP:8080` 直接可玩）
  - WebSocket `/ws`：联机通道
- 两人一房：先到为 P0，后到为 P1；第三人拒绝。
- 20Hz 批量广播玩家状态；转发射击/受击/击杀/重生/任务事件。
- 启动时打印本机局域网 IP 供房主分享。
- `--selftest`：起两个模拟客户端跑通 收发状态→射击→扣血→击杀→重生 链路（Node 22 内置 WebSocket 客户端，零依赖）。

### 协议（JSON over WebSocket）

客户端→服务器：

| 消息 | 内容 |
|---|---|
| `hello` | 昵称 |
| `state` | `{p:[x,y,z], ya, pi, hp}` 20Hz |
| `fire` | `{o:[x,y,z], d:[x,y,z]}` |
| `hit` | `{dmg}` 攻击方上报（局域网互信） |
| `dead` | 无（己方死亡上报） |
| `relay` | `{id}` 切断中继 |
| `extract` | 到达撤离点 |

服务器→客户端：`welcome{id}` / `states`（批量）/ `fire` / `hit{from,dmg,hp}` / `dead{who}` / `respawn{who,pos}` / `relay{id}` / `extract{who}` / `leave`

服务器权威范围：血量、击杀计数、重生计时、任务事件转发。伤害值由攻击方上报（刻意简化，局域网互信）。

### 客户端（原 HTML 内新增联机模块，尽量少改既有代码）

- 标题页新增"联机对战"：服务器地址输入框（默认 `ws://<当前主机>:8080`）+ 进入按钮；不进联机则走原版单机。
- 对方玩家渲染为胶囊体 + 名牌 + 血条（约 20 行，复用 `__G.scene`，不碰敌人 AI）。
- 射击命中：把对方玩家加入武器的命中检测目标；命中→发 `hit`→服务器扣血广播。
- 本地受击：收到 `hit` 调 `__G.player.damage`。
- 死亡/重生：`player:dead` 上报；服务器 5s 后广播 `respawn`，客户端调用从游戏内部暴露的重生入口回到 playing 状态，任务进度不动。
- **AI 敌人各自本地模拟**（沿用单机逻辑），仅玩家间交互与任务事件走网络。
- 任务同步：切断中继、到达撤离通过服务器广播；客户端调用内部暴露的 `cutRelayById` / `finish` 保持双方进度一致。
- HUD 增加击杀/死亡计分；死亡时显示"重生倒计时"遮罩，屏蔽单机死亡屏的重试按钮。

### 需要在原代码暴露的最小内部入口（各一处小改）

- `game.cutRelayById(id)` — 包装内部 `me()`
- `game.finish()` — 包装内部 `ee()`（撤离完成）
- `game.respawn(pos)` — 复活玩家并恢复 playing 状态

## 错误处理

- 对方断线：HUD 提示"对手已离开"，本局可继续打 AI。
- 服务器不可达：提示后留在菜单，可进单机。
- 服务器崩溃重启：客户端手动重连。

## 验证

1. `python3 server.py --selftest` 全链路自测（协议层）。
2. 手动：两浏览器（或一浏览器+一无头）输入地址互射，确认扣血、击杀、5s 重生、中继同步、撤离同步、计分板。

## 明确不做（YAGNI）

- 无房间号/多人 (>2)/观战、无断线重连续传、无延迟补偿/回滚、无反作弊（局域网互信）、无语音聊天。
